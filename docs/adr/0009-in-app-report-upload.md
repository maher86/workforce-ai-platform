# ADR 0009: Report uploads continue across employee pages

Status: accepted owner clarification 2026-11-15.

Sending a new employee report starts one tab-memory XMLHttpRequest and keeps the employee on the home screen, clearing the submitted draft only after the uploader owns its files. Amendments stay on their current report view. A persistent floating circle shows measured upload progress, then an indeterminate voice/translation phase, a check only when the server reports ready, or an X for upload/processing failure. Employees can prepare the next recording while the transfer runs. Limit each tab to one unresolved upload and 20 tracked processing reports, preserving submission/change keys and source versions for explicit retries. No submission causes navigation; the legacy /employee/upload address redirects home. Transfer completion, server receipt and AI readiness remain separate; none establishes human-verified work completion.

The uploader is bound to the authenticated employee user/device marker, cleared and aborted on identity changes. The optional upload-scope header is an additional server-side guard against an old tab's queued media being submitted after an account/device switch. It is not a credential and never replaces EmployeeContext, membership authorization or CSRF. Existing reporting services and tenant-scoped evidence policies remain unchanged. No reports, filenames, credentials or employee media enter localStorage, IndexedDB, a service-worker cache or notification content. Source media are retained only in tab memory for retry and released after acknowledgment or explicit discard. A full reload loses in-memory state, so warn before leaving and advise checking history before creating another report.

The bounded employee/report-progress batch endpoint independently resolves the employee device and scopes every report to both tenant and membership, rejecting mixed/foreign batches. It returns only ID, source version, status and phase, never source media, transcripts, translations or provider errors. Current-stage keys distinguish queued/transcribing/translating/finalizing without invented AI percentages. Poll at four seconds while visible, fifteen seconds while hidden, with non-overlapping requests, a timeout, backoff on network failure and cancellation on identity changes. Deleted own reports return withdrawn, so one withdrawal cannot stall all pending reports. Unknown network status is not failure or readiness. Older source versions and stale resumed states cannot complete newer recordings. Resume pending recent reports after home loads and notify readiness once per tracked revision.

System notifications are opt-in from the floating circle on secure supported browsers. The notification-only service worker displays generic processing-complete text only after ready and opens/focuses the employee surface; it contains no fetch, cache, push or background-sync handler. Permission denial or notification failure never blocks upload or changes report state. This narrowly extends ADR 0004's original no-service-worker implementation; it adds no offline media cache. The visual circle always works without notification permission. No spoken alerts.

This is background upload while the application/tab remains alive, not guaranteed upload after browser termination, phone suspension or loss of connectivity. The OS may suspend networking. There is no closed-app Web Push or durable background queue in this change. Deploying new assets must wait for active uploads rather than forcing reloads. Test physical Android/PWA permissions and suspension behavior separately; automated receipt tests are not physical-device acceptance.

## Upload receipt recovery and live activity (2026-11-20)

Ambiguous successful upload responses or network failures can be reconciled once through a bounded10-second GET lookup using the original submission UUID, or exact amendment UUID/report/source version. The shared FindUploadReceipt read action resolves active employee membership and selects only receipt id/status/source_version from that tenant/member; withdrawn, superseded, foreign and missing keys yield no receipt. Native key proof and X-Employee-Upload-Scope still apply. No media is re-uploaded, no AI work re-dispatched and no evidence returned. Failed confirmation retains the original body/key for explicit retry; actual server ready remains necessary for a green processing check.

Accept typed JSON/native nested JSON and BOM text with strict positive numeric ids, source-version and status validation. Late terminal/progress events cannot undo a settled receipt. Confirmation aborts on account change and cannot complete another account or amendment version. Diagnostics distinguish receipt format/content/lookup without recording raw response/evidence. Direct idempotent save response remains the primary path.

Owner clarification: Send keeps its paper-plane icon without a button loader, retains disabled/duplicate guards, and floating feedback shows progress. Successful receipt updates home/history props; open date folders invalidate cached rows on count/terminal-status changes while preserving their open state. Cancel stale day requests and use upload scope on refreshed day fetches. Physical-device acceptance remains required.
