# ADR 0011: Android employee pilot with native recording

Status: owner-authorized implementation, 2026-11-15; hardware acceptance required.

The owner requests an installable Android app because Chrome microphone permission failures and the OEM recorder's Stop / Use recording confirmation make reporting too complicated. Keep the employee icon-led React interface. Add a Capacitor Android pilot under apps/android and a small custom native microphone bridge. Do not replace the generic Laravel reporting actions or duplicate AI/business rules.

Record requests Android RECORD_AUDIO on the user's tap and records mono AAC in M4A inside the application, without an external recorder/chooser. Stop returns a bounded private clip to the existing composer; images remain optional and Send stays explicit. Original/English processing and the floating transfer/processing indicator are unchanged. No spoken commands or automatic submission. Denial exposes textual manager diagnostics and a user-invoked app-settings button. No permission bypass or claim that every device microphone is fixed.

Native capture is bounded to 180 seconds/12MB. Stop on background or native limits and return the same clip once; cancellation/identity change discards late results. Use an opaque per-session nonce, matching events and native calls. Native cache files are deleted after handoff/cancellation/destroy and stale files removed at next initialization; no external audio files, backup, media logs or credentials in JS storage. Server content sniffing, audio-only decode, duration/size quotas, tenant/source versions and private normalization remain authoritative. App termination may lose unsent drafts; no durable closed-app/background upload guarantee is added.

The first pilot loads the existing server-rendered Inertia UI from ONE build-configured HTTPS origin. This avoids recreating the employee application/API for a sideload test. Capacitor documents server.url as a development facility, so Gradle rejects release tasks. This is explicitly a debug pilot, not Play-ready architecture. Bundle a standalone employee client with a defined API/auth contract before a commercial store release. Never allow arbitrary navigation, wildcard origins, cleartext, SSL bypass or QR-selected servers. Generated configuration and APKs are ignored; no key, employee token or production configuration enters source.

The native bridge additionally checks the current origin and employee path. Its QR scanner accepts only the configured origin and exact /employee/activate#64-character-one-use-token shape. The scanner is opened by tapping the QR button in the app; it is silent and does not retain QR images. Existing manager-issued activation and secure HttpOnly revocable device cookie remain unchanged, including account-conflict handling, expiry and tenant resolution. The app has its own WebView cookies: scanning with Chrome does not transfer a login to the APK. There are no exported activation deep links or persistent credential URLs.

Disable Android cloud/device backup of WebView credentials and native files. The file provider exposes only camera Pictures output, not the private recorder cache. No system-wide settings changes. Build with pinned Capacitor dependencies and CI Android unit/lint/assemble checks; synthetic JS tests cover native races, stop-once behavior and activation URL denial. Physical microphone, OEM background behavior, QR permission, relaunch/session restore and actual submit need device acceptance.

Photo-capture follow-up: the large report camera uses a separate file input with accept=image/* and capture=environment. Capacitor8.6.2's BridgeWebChromeClient selects its camera intent only for the literal image/* accept value; a JPEG/PNG/WebP list falls through to the file picker. Keep the gallery input separate, multiple and without capture. This changes the transport hint only: server content sniffing still accepts JPEG/PNG/WebP only, with12MB/20MP/three-image limits and audio required. Android may still fall back if its camera activity is unavailable; do not claim physical capture success from a frontend build. Test the existing APK first without reinstall; a native package-visibility fix, if necessary, requires a separately signed update.

Employee home has one settings entry in the cover corner. Its shared panel contains device actions and recording assistance; remove the redundant composer settings trigger on home. Standalone report editing retains its own recording-options control, and microphone errors can still show assistance automatically. Keep the disconnect confirmation; closing/toggling the panel resets that confirmation. Native Android hides PWA installation instructions. Entry/home controls show a visible pressed state, selected settings indicator and existing real pending spinners with accessible expanded/busy labels. Respect reduced-motion preferences; no sound, new employee instructions or permission changes.

A rotating Quick Tunnel still expires: the APK's configured origin must match its QR and remain live. A fresh origin requires a new pilot build and activation; an APK does not host Laravel. Stable HTTPS hosting is required for a durable employee rollout. Debug builds use disposable Android debug signing; establish a private persistent signing key before routine app upgrades/distribution (never commit it). No merge, hosting deployment or Play publication is implied.
