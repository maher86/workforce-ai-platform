# ADR 0012: One approved employee device

Status: accepted direction; physical Android acceptance pending.

Managers issue a one-use, 30-minute activation fragment for a provisioned employee. An employee has at most one unrevoked credential. Membership row locks serialize issuing, consuming, revoking and transferring; a partial PostgreSQL unique index is the final constraint. Manager transfer requires confirmation and the expected current credential ID. It revokes the old credential and issues the replacement invitation atomically. Stale transfers fail. No report/profile history is deleted.

Invitations explicitly select `android` or `browser`; the server never trusts a submitted downgrade. Browser/PWA mode binds one browser profile through the existing encrypted HttpOnly, bounded 90-day cookie. It cannot prove a physical handset or prevent a copied browser profile. Legacy credentials retain this mode until an explicit manager transfer.

Android mode uses an app-private AndroidKeyStore P-256 key, generated per exact HTTPS origin with no employee password or biometric prompt. Activation proves possession over `workforce-activation-v1`, SHA256 of the one-use token and the public SPKI key, separated by LF. Protected requests sign `workforce-device-v1`, uppercase method, raw path with query, Unix seconds and a random 16-byte hex nonce, separated by LF. SHA256withECDSA signatures are DER/base64. Public keys never become URL credentials; private keys are not exported. Android hardware backing varies; rooted/compromised devices and hostile same-origin JavaScript are outside this guarantee. No IMEI, IP fingerprint or broad storage permission.

The cookie still identifies the credential, but cannot authenticate an Android request by itself. Verify proof before session restoration and personal HTML, JSON, profile/media access. PostgreSQL atomically rejects duplicate nonce hashes with a tenant/device composite foreign key. Accept timestamps within 600 seconds to accommodate bounded uploads; prune only after signed timestamp + 601 seconds. The scheduler deletes expired proofs in tenant-scoped batches of at most 5,000, never devices. The native signer samples the public HTTPS `/employee/device-clock` timestamp into monotonic elapsed time and refreshes every 15 minutes; phone wall-clock changes do not set the signing clock.

The native WebView signs document/media GETs; fetch/XHR wrappers sign application requests without copying multipart bodies or changing upload idempotency/progress. Cancellation while signing prevents late sends. Signature failure has no unsigned fallback. Android redirects use fresh full navigation (Inertia 409 location or a same-origin employee-only HTML redirect), avoiding replay of POST proof as GET proof. Activation obtains a cookie then navigates with a fresh GET proof. Browser behavior remains unchanged.

The session middleware records actual successful HTML/Inertia navigation, including Inertia AJAX, but excludes private binary/streamed media and JSON polling. This fixes manager validation returning to JPEG data after an avatar request under the existing no-referrer policy. QR/transfer validation also has an explicit team-page redirect so previously polluted sessions recover.

Migration 2026_11_15_000001 preserves the newest valid legacy credential per membership and retires expired/older credentials with audit records. Rollback never resurrects credentials. Apply during a controlled local/deployment update before serving the new code. Never use migrate:fresh on a populated environment. Keystore mode requires the new identity-enabled APK, Android 7+ (API 24) and a current supported WebView. Old APKs cannot activate Android-mode invitations; no silent downgrade. Stable HTTPS hosting and stable private APK signing are necessary for durable rollout. App uninstall/data reset loses the key and requires manager transfer; test before distribution.

Validation: synthetic tenant denial, replay/key/method/path/time rejection, single-use/unique-device constraints, transfer confirmation/staleness, legacy migration preservation, signed redirect behavior, manager binary redirect regression, fetch/XHR body/cancellation behavior, and a separate guarded PostgreSQL two-actor activation/transfer probe. Run the probe only after all database runners finish, with APP_ENV=testing, workforce_testing, demo provider and no OpenAI key. Physical QR, restart, photo/audio upload, transfer and upgrade acceptance remain explicit device checks.
