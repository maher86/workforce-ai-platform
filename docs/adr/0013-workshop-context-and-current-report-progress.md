# ADR 0013: Workshop translation context and current report progress

Status: implemented direction; real multilingual/device acceptance remains necessary.

The owner clarified that the current business is an automotive workshop: Arabic دولاب in vehicle context should be interpreted as tyre rather than wardrobe. Keep shared reporting actions generic and channel-independent. Store a bounded `reporting_domain` (general/automotive) on the tenant and snapshot it onto each new report from the authorized, locked tenant. The employee cannot select it in a submission payload. WORKFORCE_REPORT_DOMAIN defaults new workspaces to automotive; general remains available for other businesses. Existing tenants and reports receive general in the additive migration. Operators may explicitly configure an existing workshop with a scoped audited change before new submissions; do not mass-rewrite history. The owner-requested local workshop configuration is an operational action, not committed customer configuration.

Only translation receives the trusted domain snapshot outside the employee sources. Automotive instructions disambiguate common multilingual workshop terms, including tyre/wheel/rim, suspension and gearbox, while explicit furniture context overrides the preference. Isolated or unclear words remain uncertain. The glossary cannot create speech, quantities, work actions, replacement or completion claims. Preserve negation, plans, mixed languages and quoted hostile input as evidence. Original-language transcription remains unchanged, with automatic language detection independent of the UI locale. We deliberately do not add a fixed-language ASR hint or rewrite source text. The [official OpenAI transcription guide](https://developers.openai.com/api/docs/guides/speech-to-text) documents recording-specific vocabulary guidance, but source preservation and this multilingual requirement favor disambiguation at the separate English translation stage here.

Automotive translation output records prompt_version workforce-automotive-v1; general stays workforce-v2. Persisted reporting_domain survives configuration/tenant changes, retries and source amendments. Existing output/provenance is not regenerated on rollout; historical corrections require a separately explicit versioned action. Images remain private optional supporting attachments in text mode and are not translation inputs. Model, schema, provider calls and queue concurrency are unchanged.

The floating employee circle formerly became red if any retained report failed or was withdrawn, obscuring later uploads and successful translation. It now focuses the current upload/receipt, including an amendment to an older report ID. Without a current receipt it uses newest report ID, independently of polling order. Upload/confirmation is progress, never completion; a missing receipt status remains pending. Green requires server ready for the focused report, red indicates its real upload/processing failure, and withdrawal is neutral. Older processing remains polled/countable and older failures stay visible in a red count badge and details. A current green check does not claim all historical reports succeeded. Connection loss never manufactures ready/failed state.

Deterministic tests cover tyre vocabulary, explicit furniture, mixed languages, negation, unknown quantities, ambiguity and embedded hostile text; they verify provider request/output contracts and source preservation, not real model linguistic accuracy. Existing fidelity cases reject invented image quantities/completion and conflicting evidence. Progress regressions cover old failure/withdrawal plus new upload/ready, actual failure, missing readiness, amendments and polling order. Existing tenant-denial tests remain required. No paid provider evaluation or employee media inspection is implicit in these checks.
