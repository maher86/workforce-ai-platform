# ADR 0014: Company signup, Android-first team management and retired vehicles

Status: accepted owner direction, 2026-11-21; physical usability acceptance pending.

The owner requests a simple SaaS for any company's team. A public signup now collects company name plus owner name/email/password. CreateNewUser creates the account, tenant and owner membership in one database transaction. Request tenant/role fields cannot attach the registrant to another company or grant a global role. Email verification remains mandatory for management access. New public company signup uses general reporting context; existing tenant/report context and original/English evidence remain untouched. Legacy verified accounts without a company can still create their first company on the dashboard. A company owner is its first administrator, not a platform super-admin.

The primary manager surfaces are Reports and Team. Reports still default to today's Dubai submissions, with employee/period filters, profile history and charts. Team shows employee name, optional international phone, profile photo and phone activation status. Add employee immediately returns an Android one-use activation QR. Download app -> scan inside app -> confirm arrow is explicit in the dialog. New QR/transfer/reactivation from this screen use Android mode; browser-profile activation remains a legacy backend compatibility path but is absent from this manager flow. Existing credentials are not silently revoked, reissued or migrated. The phone is contact metadata for possible future WhatsApp, not an authentication factor or an automatic WhatsApp enrollment. WhatsApp remains deferred.

Owner follow-up removes employee access/download actions from the public landing entirely: it offers company registration and management sign-in. Android downloads are inside Team. A plain browser that opens /employee/connect returns to the public landing without a scanner or native-bridge error. This is presentation routing, not device authentication; the internal path still exists for the installed Android WebView, whose bridge enables scanning and whose server requests retain their existing cryptographic proof checks. Do not remove that shared internal route while the current native client depends on it.

Only the company owner can add or remove administrators, with current-password confirmation. Adding a new administrator provisions an ordinary non-employee user and a manager membership in the specified company, then uses Laravel's expiring, single-use password-reset broker to email a set-password link. There is no shared temporary password or employee QR. The new administrator sets their own password, signs in and completes standard email verification before management access; no second company signup is needed. Existing verified users retain their password and receive an access notification. Throttled reset requests return validation feedback instead of claiming mail was sent. Membership creation and email delivery are separate: delivery failure does not delete an already-created membership; the owner can retry. Existing configured SMTP/Mailpit is reused, not a new delivery guarantee. Email links use the configured public URL when available. Password-reset expiry/throttle and 2FA behavior remain Laravel defaults.

Vehicle routes, controllers' vehicle actions, assignment service/model, submission argument, filters, props, cards and pages are retired. Historical migrations, the vehicles table, report vehicle_id foreign key and old audit/source snapshots remain dormant to preserve data and safe upgrade/rollback. Report serialization hides vehicle_id; no active route reads or mutates those associations. No destructive migration or customer data purge accompanies feature retirement. A future schema purge requires its own retention/backup plan and authorization. Generic report activity/privacy tests survive separately from removed feature tests, and retirement tests include a historical association.

The automotive translation glossary is independent of a vehicle entity and remains available for already-configured workshops. This change does not alter AI models, prompts, original transcripts, translations, approval history, source versions, quotas or employee amendment deadlines. Removing a vehicle field does not authorize stripping car words spoken by employees. Real provider evaluation is not part of the change.

TenantAccess, active membership and per-company roles still authorize all management operations. New tests cover forged registration tenant/role, invalid signup leaving no partial account, per-company owner versus manager permissions, foreign employee QR/revocation/report identifiers, administrator onboarding/reset replay/verification, Android invitations and retained historical report evidence. Existing device proof, tenant/private media and synthetic fidelity tests remain required. No subdomain-per-company or DNS change is needed for this shared-origin tenant model. Stable HTTPS and a matching signed pilot APK remain operational prerequisites; changing a temporary tunnel origin still needs a matching build.
