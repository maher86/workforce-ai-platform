# تغطية متطلبات المنتج

الحالة: MVP قابل للتجربة ببيانات وهمية. جمع التقارير ومراجعتها يعملان؛ وضع AI الحالي محاكاة معلنة. تشغيل AI الفعلي والتجربة الإنتاجية لهما بوابات قبول مستقلة أدناه.

## المتطلبات الأصلية

| النقطة | ما نُفّذ | دليل القبول وحدوده |
| --- | --- | --- |
| 1. SaaS متعدد المؤسسات | مؤسسات وعضويات وأدوار مالك/مدير/موظف، وصلاحيات لكل مؤسسة | اختبارات مؤسستين، موظفين في المؤسسة نفسها، وإلغاء الصلاحيات؛ قيود PostgreSQL المركبة ومسار المرفق |
| 2. SaaS/PWA أولًا | واجهة موظف مستقلة، أيقونة وmanifest، تسجيل وكاميرا ورفع بديل، وحالة اتصال | المستخدم أكد إضافة الأيقونة على Android؛ تسجيل الميكروفون والكاميرا وأذونات الرفض على الأجهزة الفعلية يحتاج تجربة ميدانية |
| 3. WhatsApp لاحقًا | لم يُنفّذ اتصال WhatsApp أو Meta | مؤجل حتى الموافقة؛ لا تعتمد خدمات التقارير على مزوّد مراسلة |
| 4. منطق مشترك للقنوات | SubmitReport وMediaInput وخدمات المراجعة والمعالجة تستقبل هوية ومؤسسة صريحتين | طلبات HTTP والملفات المرفوعة تُحوّل إلى مدخلات التطبيق في controllers؛ المهام تحمل المعرّفات فقط |
| 5. صوت وصور ونص ومزيج | تسجيل حتى 3 دقائق، تسجيل واحد وثلاث صور، نص اختياري، وتهيئة الملفات الخاصة | اختبارات FFmpeg فعلية، WebM متدفق بلا رأس مدة، ورفع متعدد عبر HTTPS وطابور Redis الفعلي |
| 6. لا تُشترط مهمة أو مشروع | كلا الارتباطين nullable، والإرسال الافتراضي بلا اختيار | اختبار نص وملفات بلا ارتباط؛ رفض معرّفات مؤسسة أخرى |
| 7. مهام المدير اختيارية | إنشاء مشاريع ومهام وإغلاقها؛ إغلاق المشروع يغلق مهامه | ارتباطات محمية بالمؤسسة وتحقق من المشروع الأب، مع بقاء التقارير السابقة |
| 8. OpenAI ومتعدد اللغات | موصل Transcriptions وResponses، نص أصلي منفصل وترجمة إنجليزية وتقرير منظم | عقود API مختبرة بطلبات وهمية؛ المفتاح المحلي والتقييم الفعلي للكلام متعدد اللغات لم يُنجزا بعد |
| 9. صور بلا اختلاق كميات أو إكمال | ملاحظات غير مؤكدة، اقتباس من نص/صوت لأي كمية أو إكمال مُبلّغ، ومراجع أدلة صحيحة | التقرير المصور فقط لا ينتج ادعاءات عمل تلقائية؛ اختبارات كلام غير واضح/لغات مختلطة/غياب كمية/تعارض/تعليمات خبيثة. التحقق البنيوي لا يثبت صحة المعنى؛ مراجعة بشرية وتقييم حي مطلوبان |
| 10. الحزمة التقنية | Laravel وReact/TypeScript وPostgreSQL وRedis وCompose وActions | بناء واجهة وتحليل PHP وفحوص بنية فعلية؛ FFmpeg مضاف لصورة التطبيق |
| 11. Jobs/Queues/Events/Scheduler | حدث بعد الالتزام، مرحلة API واحدة لكل job، قفل صريح وحفظ النتائج واستعادة المتوقف والاحتفاظ | دورة HTTPS فعلية وصلت إلى ready بأربع نتائج محفوظة؛ فشل مع رسائل منقّحة وإعادة محاولة ومراجعة يدوية مستقلة |
| 12. بلا n8n أو Kubernetes | لا يوجد أي منهما | تطبيق Laravel موحد معياري وخدمات Compose |
| 13. Issues وفروع وPR واختبارات | #1–#13 وخطة قبول، PR #14 مدمج في dev، وPR #15 للدخول | فرع التقرير يعتمد مؤقتًا على PR #15 المفتوح؛ لا دمج تلقائي ولا نشر إنتاجي |
| 14. حوكمة Codex | AGENTS ومهارتا العزل والدقة وADRs وتسليم دائم | توثيق حدود النتائج والأخطاء الفعلية، ومنع تشغيل فحصي قواعد بيانات على workforce_testing معًا |
| 15. مستودع عام بلا أسرار أو بيانات | تجاهل env وملفات الموظفين والنتائج المحلية، وفحص أسرار محلي وفي CI | بيانات اختبارات وهمية فقط؛ قيم النفق والمفاتيح والنسخ الاحتياطية الفعلية لا تُحفظ في Git |

## سهولة استخدام الموظف

المدير يضيف الموظف ويعطيه QR/رابطًا مؤقتًا لمرة واحدة. الموظف لا ينشئ حسابًا ولا يكتب بريدًا أو كلمة مرور. بعد التفعيل، تفتح الأيقونة الحساب ما دام اعتماد الجهاز صالحًا. تظهر ثلاثة إجراءات رئيسية: ميكروفون، كاميرا، إرسال. التعليمات الصوتية العربية تعتمد على صوت متاح في الجهاز، ويمكن للمدير المساعدة عند أول تثبيت/إذن.

تحتاج النصوص الصوتية واللغات والصور التعريفية ووضوح الرموز إلى جلسة استخدام مع عمال مستهدفين قبل الطيار. الاختبار الآلي لا يثبت قابلية الاستخدام لغير القارئ. الهواتف المشتركة بين عدة موظفين تحتاج تصميم تبديل هوية مستقل؛ النموذج الحالي هاتف مخصص للموظف.

## ما يعمل للمدير

- قوائم مفلترة حسب الموظف والحالة والتاريخ، ومرفقات خاصة قابلة للتشغيل، ونص أصلي وترجمة وملاحظات منفصلة.
- مراجعة إنجليزية مع سبب وإصدار متزايد، ومنع حفظ نموذج مراجعة قديم فوق مراجعة أحدث؛ النتائج المولّدة تبقى محفوظة.
- مراجعة يدوية عند فشل AI مع إبقاء حالة الفشل واضحة. إعادة المعالجة تعيد حالة المراجعة إلى pending وتحفظ الإصدارات السابقة.
- CSV يحوي اسم الموظف وحالة المعالجة والاعتماد ومصدر AI؛ منع الصيغ التنفيذية وتحديد البيانات بالمؤسسة.
- المالك يضيف حساب مدير مؤكدًا ويوقفه بعد تأكيد كلمة مروره. مدير QR لا يُمنح صلاحيات إدارية. حساب مرتبط بمؤسسة لا يُحذف ذاتيًا فيتركها بلا مالك.
- إعادة تفعيل الموظف تصدر QR جديدًا ولا تعيد اعتماد أجهزته الملغاة.

## بوابات إكمال الطيار التجاري

1. إعداد مفتاح OpenAI محليًا وموافقة الاختبار المدفوع، ثم تقييم كلام وصور وهمية معتمدة بلغات الموظفين، ومراجعة بشرية للدقة والامتناع عن اختلاق حقائق. أمر ai:evaluate يختبر نصوصًا وهمية فقط، ولا يستبدل تقييم الكلام والصور.
2. تجربة Android وiPhone فعليًا: سماح/رفض الميكروفون، تسجيل/إيقاف/خلفية، كاميرا ومعرض، انقطاع الشبكة، الإرسال المكرر، وإلغاء الجهاز. أيقونة Android وحدها لا تغطي هذه الحالات.
3. اختيار عنوان HTTPS ثابت وخادم وبريد وتخزين ونسخ احتياطية مشفرة خارجية، مع سياسات المزوّد والاحتفاظ وحدود الإنفاق. النفق الحالي معاينة مؤقتة فقط.
4. التحقق من النسخة الإنتاجية ونسخ قاعدة التطبيق والوسائط معًا واستعادتها، وصحة العامل والجدولة والمراقبة، ثم موافقة نشر صريحة. اختبار النسخ الحالي يستخدم قاعدة اختبار وملفات وهمية ويترك قاعدة التطبيق دون تغيير.
5. دمج PRs المعتمدة إلى dev، ثم إصدار مضبوط إلى main. لم يُصرّح بهذه الدمجات أو نشر الإنتاج ضمن طلب إكمال الكود.

الفوترة الآلية والتحليلات المتقدمة والمزامنة الكاملة دون اتصال وWhatsApp تبقى خارج MVP المعتمد. الاشتراكات والحصص يمكن إدارتها يدويًا في الطيار.
